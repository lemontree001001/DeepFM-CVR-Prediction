第一：数据基建与“防穿越”屏障
【动作】：不使用随机打乱（Random Split），而是严格按照时间先后顺序，将历史数据划分为训练集（train_set），将最后一天或几天的未来数据划分为验证集（val_set）。
【为什么引入】：真实商业世界的时间是单向流动的。如果我们用随机划分，模型就会“偷看”未来的信息（比如提前知道某件商品明天会成为爆款）。
【优势与成果】：建立了一套严谨的、与真实线上环境完全一致的评测基准。虽然初期跑分可能很难看，但这里跑出来的 AUC 是绝对真实、没有水分的。

第二：模型破局 —— 从 XGBoost 到 DeepFM
【动作】：项目初期我们尝试了经典的 XGBoost 树模型，随后全面迁移到了基于 PyTorch 的 DeepFM 深度神经网络。
【为什么放弃 XGBoost】：

ID 特征的梦魇：XGBoost 的底层是决策树，它通过判断数值的“大小”来切分节点（比如 user_id < 5000）。但用户 ID 和商品 ID 纯粹是编号，大小没有任何数学意义。XGBoost 面对这种极其稀疏的离散 ID 彻底抓瞎，导致 Baseline 只能在 0.53 左右徘徊，和瞎猜差不多。
【引入 DeepFM 的巨大优势】：

万物皆可 Embedding：DeepFM 引入了 Embedding 机制，为每一个毫无规律的 ID 生成了一个蕴含隐含特征的稠密向量（比如 4 维空间的一个点）。

自动特征交叉：FM（因子分解机）模块会自动计算“用户向量”与“商品向量”的内积，极其敏锐地捕捉到类似“这个北京的学生，偏爱这家数码店”的高阶组合规律。DeepFM 让分数有了提升。

第三：动态特征挖掘与冷启动模拟
【动作】：利用 Pandas 的 groupby，统计了用户的历史点击次数（活跃度）和商品的历史被点击次数（全局热度）。极其关键的是：仅仅在 train_set 上进行统计，然后 LEFT JOIN 贴回全局。
【为什么这么做】：

仅仅知道 ID 是不够的，必须给模型注入先验的统计规律（爆款更容易卖，活跃用户更容易买）。

防穿越与冷启动：如果在总表上统计，就泄露了验证集的天机。只在训练集上统计，并用 fillna(0) 填补验证集，完美模拟了现实中遇到“新注册用户”和“刚上架新商品”的冷启动场景。

第四：化解特征吞噬 —— 连续特征分桶 (Bucketing)
【动作】：引入 KBinsDiscretizer，使用等频策略（Quantile），将连续的价格、活跃度、商品热度强行切分为 10 个桶，转化为 0~9 的离散类别，并统统扔进 Embedding 层。
【为什么引入】：

数据长尾灾难：电商点击量极其不平衡，有人点 1 次，有人点 10000 次。如果不分桶，这 10000 会产生巨大的梯度，掩盖掉其他所有特征，导致模型产生“只要点击量高就买”的错觉（特征吞噬）。
【优势与成果】：

打破了线性枷锁，模型不再做死板的乘法，而是为不同区间（如“便宜货”、“轻奢”、“天价”）分别学习向量，极其精准地刻画了非线性的商业规律。这一步让模型分数逼近 0.60。

第五：降维打击 —— 负采样 (Negative Sampling) 破局样本失衡
【动作】：针对正负样本 1:100 的极度倾斜，在 train_set 中随机丢弃大量未购买记录，将正负比例强制压缩至 1:10，并全局打乱（Shuffle）。
【为什么引入】：

打破“躺平骗分”机制：在 1:100 下，模型发现只要全部预测“不买（0）”，准确率就能高达 99%。为了降低 Loss，模型选择“摆烂”，不去认真学习真正的分类边界。
【优势与成果】：

逼迫模型去寻找买与不买的本质区别。不仅让极其庞大臃肿的训练集极速“瘦身”（训练速度提升 10 倍以上），更是让 AUC 迎来了提升，达到了 0.6190。

第六：极限防御 —— 早停与正则化压制过拟合
【动作】：在 DeepFM 网络中注入 L2 正则化（Weight Decay）和 Dropout，并引入验证集监控机制（Early Stopping），一旦验证集 AUC 停止增长，即判断为达到极限。
【为什么引入】：

经过负采样后，训练集只剩下数千条数据。DeepFM 庞大的参数量极其容易将这几千人“死记硬背”下来（Train AUC 飙升至 0.99），导致面对验证集时彻底懵圈（泛化能力崩塌）。
【优势与成果】：

L2 惩罚极端权重，Dropout 随机戳瞎神经元，强制模型学习普适规律而不是死记特例。模型最终稳稳锁定在最高战力点，不再发生验证集分数随着 Epoch 增加而暴跌的悲剧
